# Markdown 与 Obsidian 对照审查

日期：2026-10-14。范围：现有 Markdown 编辑、实时预览、阅读预览和格式按键；依据 Obsidian 官方语法文档及本项目的实际源码与 Electron 检查。没有启动 Obsidian 做逐项界面对比，因此这里不承诺全部交互与 Obsidian 完全相同。

参考：[基本语法](https://help.obsidian.md/syntax)、[高级语法](https://help.obsidian.md/advanced-syntax)。

## 2026-10-27 按用户习惯调整按键

- 列表正文中间的 Enter 拆成同类型的两项；空子项再按 Enter 返回上一级，空引用逐层退出。已完成待办续行生成未完成的新待办。
- 列表正文 Shift+Enter 在同一项内新增续行，对齐正文；标题中间 Enter 后半成为普通正文。
- 围栏代码内非空行的 Enter 继承原始空格或 Tab。空缩进行 Enter 在原行减少四列、不增加空行；空行已无缩进时沿用普通换行。
- Tab／Shift+Tab 只调整当前物理行，选中多行时只调整选区涉及的行；未选中子项的文字和缩进不动。普通正文行首 Tab 仍是四列缩进代码块。混合空格与 Tab 在退缩进时尽量保留未删除的原字符。
- 调整有序项层级时，只重排结构受影响的有序列表组；新子列表从 1 开始，未选中后代和不相关编号保留。插入新有序项时现有 Markdown 命令会顺延其后同级编号。
- 顶层非空列表项正文开头 Backspace 移除该项标记并保留文字；需要时补标准 Markdown 空白分隔行，使编辑和阅读都成为顶格段落，同时防止后续有序项被吞进正文。所有改动一次撤销。列表行尾 Delete 保留原生源码合行行为，包括下行的列表标记。
- 只含四个空格或一个 Tab 的行首缩进，退格按一级删除；列表正文中的空格仅输入间距。
- 粘贴纯文本多行到空列表项时，每行成为同级项目；粘贴已有 Markdown 列表时调整到目标层级，保留内部层级、标记及任务状态。新生成的待办默认未完成。有序编号与粘贴合成一次撤销；无法安全确认结构的混合内容保留原粘贴路径。
- 选中文字后直接键入成对格式符号会包裹原文，再输入相同格式会取消；两个物理按键组成的一次格式操作支持一次撤销。未选中文字时，Markdown 格式符号按输入保留，结束符号手动输入；空标记中的 Backspace 按普通源码删除左侧字符。
- 同一表格源码单元格内的文字被选中时，Tab／Shift+Tab 保留文字并跳到相邻单元格。跨单元格或多行的选区沿用普通多行缩进规则；末格 Tab 新增行仍支持一次撤销。

## 2026-10-26 编辑体验修整

本节取代下面历史记录中已经过时的图片缺项描述；旧验证记录保留。当前仍是连续 Markdown 源码加 Live Preview，不是段落编辑器，也不承诺与 Obsidian 所有设置逐键相同。

- 行内格式按光标所在语法范围展开；同行其他格式保持预览。任务正文保留复选框，进入列表／任务前缀后可编辑原始标记；跨行选择仍可访问原文。
- 硬换行的反斜杠仅在源码激活时显示。行内代码按 CommonMark 处理边缘空格和源码换行，显示与点击复用 UTF-16 投影；引用／列表续行前缀不计入代码内容。
- 表格仍编辑源码：Tab／Shift+Tab 按单元格移动，包含表头、跳过分隔行；首格 Shift+Tab 停留。末格 Tab 新增同列数空行并定位第一格，一次撤销可移除。新增行保留引用、列表容器前缀，不复制列表标记。竖线仍遵守 GFM 转义规则。
- 空列表正文起点按 Backspace，嵌套项退一层；顶层项清完整前缀及缩进。引用等外层容器保留。普通段落 Tab、非空项删除和 Enter 续写不改变。
- 图片在编辑区预览；单击展开源码，Ctrl+单击打开原图。缺失或无法打开的图片保留源码入口。本地资源仍受主进程目录授权和位图类型检查约束。
- 单张 PNG／JPEG／WebP 截图可直接粘贴为相对附件引用，最多 20 MiB。含正文的富文本沿用原粘贴规则。每文档最多 8 项待处理任务、40 MiB 预留数据。
- 图片操作绑定发起时的原笔记和选区，位置随编辑映射；原选区发生修改后只追加插入，不覆盖新文字。切换标签可继续处理；最后视图关闭、退出或路径变更前必须排空队列并保存。失败显示原目标的重试／取消入口，已保存附件不重复创建，撤销只移除引用。
- 待处理队列只在本次运行内存在，不承诺跨重启续传，不自动清理无引用附件。版本与交付状态以本轮验证记录为准，源码检查不代表已打包。
- 临时标签包含正在处理的图片时会自动保留；取消任务不视为后台写入已经结束。选区跨越代码块时拒绝成对格式操作并保留原文。
- 有序列表粘贴后，同级条目的续行和子项不阻断编号顺延；单个尾随换行产生的宽松列表仍顺延。

以下为历史审查记录。

### Tab 的确定规则（历史）

用户确认以 Obsidian 为准。官方文档明确说明：普通文本前的 Tab 或四个空格创建代码块；列表中的 Tab／Shift+Tab 用于缩进和取消缩进。

- 已有父列表下的子条目使用 Tab 后仍是 Markdown：加粗、斜体、删除线、高亮、待办等继续渲染。
- 普通段落或没有父列表的单独缩进行仍是代码块，其中 `**`、`#` 等按原文显示。
- 保存真实 Tab，按四列显示。没有取消缩进代码块解析，没有改写用户的原始笔记。

### 列表缩进引导（2026-10-18）

引导线按列表层级绘制，覆盖条目续行、同条目内的空行和后续段落；一层一条，不按空格数量重复。默认淡灰，光标所在条目的层级使用柔和红色；Tab 与空格按实际列宽计算。普通正文空格不画线，引用保留引用线，代码块保留自身样式；这些显示装饰不改写 Markdown。

### 列表正文对齐（2026-10-24）

有序、无序列表统一使用两字宽的标记区，首行与自动换行对齐正文；混合嵌套列表的续行、后续段落和引导线按同一视觉位置计算。编辑中的原始标记也预留相同宽度，阅读模式采用同一个缩进值。原始编号、空格、Tab、中文及 Emoji 的 UTF-16 位置不改写。

## 本轮修复依据与代码

1. `markdownCommands.ts`：CodeMirror 默认会把紧列表的第二个空条目转为松散列表。配置 `nonTightLists: false` 后，连续 Enter 立即退出一层。空嵌套引用只删除最内层引用标记。
2. `markdownLinks.ts`、`markdownLivePreview.ts`、`markdownCommands.ts`：Lezer 会把尚未定义的引用候选也标为 `Link`。现在先确认显式目标或引用定义，再隐藏括号或取消链接；引用缓存同时核对语法树和文档文本身份。
3. `markdownParser.ts`、`markdownRendering.ts`、`markdownLanguage.ts`：Marked 默认支持单波浪线删除线，编辑端却不按此渲染。现在阅读端要求双波浪线，编辑端去掉阅读端没有的上下标和表情别名解析。HTML 清理仍由 `renderMarkdown` 的 DOMPurify 执行。
4. `markdownLivePreview.ts`：新增自动链接装饰，并限制缩进提示只能覆盖真实空格／Tab。

## 已确认的兼容缺项

以下是尚未实现的功能，不能称为与 Obsidian 完全兼容：

- `[[双链]]`、别名、标题／块引用和 `![[嵌入]]`。
- Callout 的类型、折叠和专用样式。普通引用已有支持。
- 引用脚注与内联脚注。
- `%%注释%%`。
- `$公式$`、`$$公式$$` 与 Mermaid 图表。
- Obsidian 的彩色高亮标记，例如 `==🔴文本==`；当前仍使用统一高亮色。
- 任意字符待办状态，例如 `- [?]`、`- [-]`；当前只识别空格及 x／X。
- 图片阅读预览已有支持，编辑区还没有对应的图片 Widget。
- 代码按语言着色、表格右键增删和移动行列、Ctrl／Cmd 点击编辑区链接等完整编辑交互。

这些内容没有在本轮批量加入，避免把语法审查扩大为尚未确定的跨文件导航、数学及图表渲染改造。
