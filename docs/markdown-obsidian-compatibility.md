# Markdown 与 Obsidian 对照审查

日期：2026-10-14。范围：现有 Markdown 编辑、实时预览、阅读预览和格式按键；依据 Obsidian 官方语法文档及本项目的实际源码与 Electron 检查。没有启动 Obsidian 做逐项界面对比，因此这里不承诺全部交互与 Obsidian 完全相同。

参考：[基本语法](https://help.obsidian.md/syntax)、[高级语法](https://help.obsidian.md/advanced-syntax)。

## Tab 的确定规则

用户确认以 Obsidian 为准。官方文档明确说明：普通文本前的 Tab 或四个空格创建代码块；列表中的 Tab／Shift+Tab 用于缩进和取消缩进。

- 已有父列表下的子条目使用 Tab 后仍是 Markdown：加粗、斜体、删除线、高亮、待办等继续渲染。
- 普通段落或没有父列表的单独缩进行仍是代码块，其中 `**`、`#` 等按原文显示。
- 保存真实 Tab，按四列显示。没有取消缩进代码块解析，没有改写用户的原始笔记。

### 列表缩进引导（2026-10-18）

引导线按列表层级绘制，覆盖条目续行、同条目内的空行和后续段落；一层一条，不按空格数量重复。默认淡灰，光标所在条目的层级使用柔和红色；Tab 与空格按实际列宽计算。普通正文空格不画线，引用保留引用线，代码块保留自身样式；这些显示装饰不改写 Markdown。

### 列表正文对齐（2026-10-24）

有序、无序列表统一使用两字宽的标记区，首行与自动换行对齐正文；混合嵌套列表的续行、后续段落和引导线按同一视觉位置计算。编辑中的原始标记也预留相同宽度，阅读模式采用同一个缩进值。原始编号、空格、Tab、中文及 Emoji 的 UTF-16 位置不改写。

## 本轮修复依据与代码

1. `markdownCommands.ts`：CodeMirror 默认会把紧列表的第二个空条目转为松散列表。配置 `nonTightLists: false` 后，连续 Enter 立即退出一层。空嵌套引用只删除最内层引用标记。
2. `markdownLinks.ts`、`markdownLivePreview.ts`、`markdownCommands.ts`：Lezer 会把尚未定义的引用候选也标为 `Link`。现在先确认显式目标或引用定义，再隐藏括号或取消链接；引用缓存同时核对语法树和文档文本身份。
3. `markdownParser.ts`、`markdownRendering.ts`、`markdownLanguage.ts`：Marked 默认支持单波浪线删除线，编辑端却不按此渲染。现在阅读端要求双波浪线，编辑端去掉阅读端没有的上下标和表情别名解析。HTML 清理仍由 `renderMarkdown` 的 DOMPurify 执行。
4. `markdownLivePreview.ts`：新增自动链接装饰，并限制缩进提示只能覆盖真实空格／Tab。

## 已确认的兼容缺项

以下是尚未实现的功能，不能称为与 Obsidian 完全兼容：

- `[[双链]]`、别名、标题／块引用和 `![[嵌入]]`。
- Callout 的类型、折叠和专用样式。普通引用已有支持。
- 引用脚注与内联脚注。
- `%%注释%%`。
- `$公式$`、`$$公式$$` 与 Mermaid 图表。
- Obsidian 的彩色高亮标记，例如 `==🔴文本==`；当前仍使用统一高亮色。
- 任意字符待办状态，例如 `- [?]`、`- [-]`；当前只识别空格及 x／X。
- 图片阅读预览已有支持，编辑区还没有对应的图片 Widget。
- 代码按语言着色、表格右键增删和移动行列、Ctrl／Cmd 点击编辑区链接等完整编辑交互。

这些内容没有在本轮批量加入，避免把语法审查扩大为尚未确定的跨文件导航、数学及图表渲染改造。
