# macOS 构建与验证

从 0.3.3 起提供 Mac 平台测试包。同一 Electron 代码库需要针对不同系统和 CPU 分别打包；构建成功不等于所有平台功能已经得到完整验证。统一发布入口会先上传经过检查的 Windows 包，再运行原生 Mac 构建；三个包都核对成功后才公开新版本。

## 构建方式

在 GitHub Actions 手动运行 **Build and publish macOS packages**，输入已有发布标签。标签的版本必须与工作流所选分支或标签的 `package.json` 一致。

- `macos-15`：原生 Apple Silicon / arm64 构建。
- `macos-15-intel`：原生 Intel / x64 构建。
- 使用锁文件安装依赖、构建前端、运行全部单元测试，随后生成 DMG。
- macOS 图标由现有构成主义 PNG 生成 ICNS，未换用旧图标或新概念图。
- 包内只保留 Electron 主进程、前端产物、会话共享模块及 OCR 必需的 Node 依赖；OCR 语言资源沿用仓库资源。

两种架构均通过定向包内检查之后，发布任务才将 DMG、架构验证记录及独立 Mac 校验清单附加到已有 Release。已有 Windows 安装包与其校验文件不覆盖；同名但内容不同的 Mac 文件也不会静默覆盖。

GitHub 私有仓库的 macOS 工作流会使用账户的 Actions 分钟额度；这里没有开通额外付费服务，也没有设置自动定期构建。

## 当前验证边界

定向检查包含：真实包版本及关键文件哈希、OCR 模块与语言资源、Markdown 输入/保存/撤销/重做、PDF 显示与查找、EPUB 显示、macOS 文件事件路由、原生退出菜单（Cmd+Q 的菜单入口）触发未保存内容写盘、V3 会话重启恢复，以及原 PDF/EPUB 文件不被修改。自动化直接调用退出菜单，不代表已经验证真实键盘快捷键或 Finder 双击。

路径处理同时支持 Windows 路径和 POSIX 路径，不把 Mac 路径改成反斜杠或无条件折叠大小写。已有 Windows 数据保护和图标断言继续保留。

仍须后续真实用户验证：Finder 文件关联、输入法/多显示器、原生文件对话框、跨页拖选和摘录、所有主题/布局及不同 Mac 型号。不能把本轮定向测试称作完整 Mac 发布回归。

## 签名与字体

目前只做 ad-hoc 完整性签名，未使用 Apple Developer ID，也没有 Apple 公证；Gatekeeper 可能阻止首次打开。不要将其描述为已获 Apple 认证的正式分发版，不提供批量关闭系统安全检查的命令。

正文系统字体仍需对应机器安装，汉仪书仿 55W 不包含在源码或安装包内。Windows 与 Mac 的本机字体不一定相同，未安装时会使用现有字体回退链。

不在用户的 Windows 工作站下载或安装 Mac 运行包。构建与验证发生在 GitHub 的临时 Mac 环境。
